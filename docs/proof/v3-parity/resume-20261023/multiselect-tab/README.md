## Policy and implementation

Pinned source `a76e57c9bbc2837e96420b2610e9c82a3271bb05` has no Tab handler in `trigger.tsx`. In `context.tsx`, an open select listens for `focusin` and closes only when the destination is outside both its root and popup. Closing proposes an empty query. The input's `onFocus` proposes opening. These source files are retained and checked against the pin, with the complete JavaScript bundle input closure archived separately.

The candidate observes primary-focus destination changes, checks both trigger and popup ancestry, closes on an external focused node, and opens on input entry. Temporary null focus and scope-only focus are not external input destinations. It does not close on arbitrary input blur or intercept Tab. The input's keyboard-handler wrapper skips traversal. Controlled query proposals now leave the controller showing the owner's effective query even when the owner does not rebuild. Pointer selection inside the popup stays open.

The r2 same-node owner repro is confirmed in `precedence-confirmed.log` against the immutable prior candidate, and in `precedence-red.log` against the in-progress repair. Repeating `requestFocus()` on an already-primary external node does not produce a distinguishable focus change. When a chip action starts with external focus, the repair synchronously claims and applies input focus before invoking the selection owner. An explicit owner request back to that external node is then observable and wins over the deferred chip-focus callback. Without an override, the ordinary external-input-to-chip action still focuses the input. The deferred guard no longer accepts an arbitrary unchanged external node. It allows unchanged scope-only initial focus, temporary null focus, or focus within the select, while retaining generation, mounting and disabled guards.

This deliberately changes callback ordering for chip actions that start with external focus: input focus/open may occur before the selection callback. It is not a claim that Flutter exposes redundant same-node focus requests. Exact same-node precedence and its no-override control are widget-level evidence; native recordings cover the subsequent external pointer intent, not callback/microtask ordering. No programmatic browser focus was used.

## Verification and limits

Run `python3 verify.py` with Python, Pillow, ffmpeg and ffprobe. It requires no checkout, browser, network or package installation. Input locks, source bindings, archive hashes, exact served bundles, every screenshot and original screencast frame, and RGB-exact frame-index replay decoding are checked. Independent assertions verify Tab and return destinations, popup/query state, exact callback deltas, selection stability, control rejection, Escape/retyping, external intent and disposal. `verification-summary.json` and `verify-export.json` record in-place and regular-file portable-export verification.

The timestamp MP4 and 25fps frame-index replay have different purposes. The verifier reports timestamp MP4 decoded counts separately; it does not assert timestamp replay is frame-complete or RGB-exact. The frame-index replay preserves all original frame content and order at a synthetic fixed rate, not original timing. Original PNGs, capture timestamps, inputs, screenshots and encoding logs remain available. No animation timing, 60fps, screen-reader session, physical-device, mobile, minimum-SDK, hosted-CI, full keyboard parity or release-readiness claim is made. Independent r2 reviewed the immutable prior snapshot; its findings were reproduced and repaired here, but it has not independently reviewed this final implementation.

Servers use checked-free ports 18179 and 18180. `servers.json` identifies the owned processes; only those are stopped after capture.
