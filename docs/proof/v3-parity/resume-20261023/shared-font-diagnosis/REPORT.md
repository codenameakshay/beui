## Findings

1. **There is no demonstrated wrong Geist asset revision.** The static candidate sans is Geist 1.800; mono is Geist Mono 1.701. The archived live WOFF2 fonts have the same revisions. They have only the `wght` variable axis, range 100–900, default 400; no optical-size axis. All have 1000 units/em and hhea ascent/descent/lineGap 1005/-295/0. Instantiating archived source at 400 yields identical outlines and horizontal metrics for all 225 shared encoded glyphs in both families. Different compressed-file hashes do not imply different typefaces.

   At 500/600/700, static versus variable outlines differ numerically. For simple glyph coordinates, maximum deltas are 0.499908, 0.497453, 0.500305 font units for sans and 0.499908 for mono 500. Rounding variable coordinates to integer font units eliminates all measured coordinate differences at 500/600 and mono500, leaving two coordinate mismatches at sans700. At 12px this is about 0.006px. ASCII horizontal metrics match at every tested weight. These are static-instantiation precision differences, not evidence of a wrong font or weight axis. `font-comparison.json` retains raw outline comparisons; `interpolation.json` refines their interpretation. Neither analysis proves identical browser hinting/raster output.

2. **The gallery config requests the intended families, but public mono defaults bypass the named mono contract.** `example/pubspec.yaml:36-64` registers sans weights 400/500/600/700 and mono weights 400/500 under both `Geist Mono` and `monospace`. `example/lib/explorer/explorer_app.dart:71-72` installs Geist and neutralizes Material tracking. Both chart fixtures call this theme. `lib/src/theme/beui_text_theme.dart:30-43` names Geist Mono but loads nothing. `lib/src/theme/beui_agent_theme.dart:70-73` instead hard-codes `monospace`, with the same name as its only fallback. File diff also hard-codes it at `lib/src/motion/file_diff.dart:464`, 907, 921, 1146. Chart numeric styles do likewise.

   A consumer that correctly registers only the documented named Geist Mono family will not thereby satisfy those literal `monospace` requests. That is a demonstrated configuration-contract mismatch. The gallery's alias is a workaround, not a library font-loading guarantee. Do not claim that browser generic monospace necessarily supplies a usable CanvasKit font. The engine separately loads Roboto as its fallback; a Roboto response alone is normal startup behavior, not proof that a particular glyph fell back.

   **The gallery alias is not unconditionally broken.** `canvaskit-probe.cjs` loads the archived bump build's actual chromium CanvasKit and its font manifest/assets. At 12px, both aliases give 72px for ten zeros, ten i's, and ten W's, at 400 and 500. Reversing family registration order leaves those measurements unchanged. The probe also exercises single-weight registrations. This is a font-provider measurement, not proof of each archived application paragraph's resolved font. The engine asset-loader logic in candle fixture `main.dart.js:19770-19865` registers each family explicitly; its bundled generic-font predicate at 1380 is part of CSS-family formatting and does not by itself establish CanvasKit alias rejection.

   The v13 fixture's reported narrow mono appearance remains UNRESOLVED. Matching manifest, downloaded bytes, and a successful direct provider probe cannot certify the selected face at every application label. There is insufficient evidence to call its cause rasterization, alias loss, or a load race. A targeted follow-up should measure actual application paragraph advances for `iiiiiiiiii` and `WWWWWWWWWW` under each family and capture load completion; do not change all fonts on speculation.

3. **Ticker geometry is a real shared implementation mismatch.** `lib/src/charts/_shared.dart:464-470` forwards the caller's style into BeuiNumberTicker unchanged. `lib/src/motion/number_ticker.dart:177` chooses explicit style or ambient style rather than resolving their merge; at 321 it uses 14 if an explicit partial style omits size. Text itself can still inherit the ambient size. This creates inconsistent geometry for partial-style callers. The confirmed volume call supplies 12px, so that partial-style defect is not its current size error.

   Independently, line 323 uses `fontSize * 0.62`. Source `components/motion/number-ticker.tsx:173-181` uses `1ch`, and lines 170-172 describe its real text baseline. Geist Mono zero advance is 600/1000 em, so a 12px slot should be 7.2px; candidate allocates 7.44px. Six digit slots accumulate 1.44px extra width, excluding separators. The CanvasKit probe independently gives 72px for ten mono zeros. Candidate's row uses crossAxisAlignment.center at line 225 while source uses `items-baseline` at source line 99. Source always supplies `tabular-nums`; candidate ticker does not inject FontFeature.tabularFigures. Missing tabular figures matters for sans callers; Geist Mono already has fixed advances. Source digit slot line-height overrides inherited line-height, while candidate digit Text keeps its inherited height inside a centered box. These require a scoped ticker geometry/typography correction, not per-chart padding compensation.

4. **The file icon is the wrong glyph.** Pinned `components/agents/file-diff.tsx:7,173` uses FileCode2. Candidate `lib/src/theme/beui_agent_theme.dart:529` maps `file` to LucideIcons.file_code, consumed at `lib/src/motion/file_diff.dart:894`. The installed flutter_lucide exposes `file_code_corner` (1.11.0 source line 7230, codepoint 0xe45e), which represents the corresponding corner-code glyph. This is not a text font/raster issue. Change the shared agent mapping, retaining the override API; no package migration is needed.
