# Combobox exit recovery

Recovery preserved the saved implementation and all prior artifacts after provider failures. The implementation retains the last rendered open query for exiting items and groups while the input uses the effective query. No Dart changes were made during this recovery. No children, commits, pushes, shared overlay changes, other-worker edits, broad suites, or goldens were used.

## Result

The focused non-golden suite passes all 21 tests and the two-file analyzer reports no issues. `test-recovery.log` and `analyze-recovery.log` were produced in the isolated candidate checkout with the exact owned source and test hashes. The tests cover Escape, selection, no-results, mid-exit reopen under both motion preferences and all four combinations of accepted/rejected controlled close/query proposals. Original red and green logs remain unchanged. An initial recovery command used `--plain-name` with a regex and ran no tests; its error and isolated dependency resolution are disclosed in `test-recovery-invocation-error.log`. The corrected command used `--no-pub --name 'BeuiCombobox interactions|exit filtering'`.

Native acceptance is incomplete. In `native-recovery-1/candidate-reduce`, after selection and a no-results cycle, Escape followed about 25ms later by ArrowDown and trusted replacement typing leaves `apl` in the input but no popup. The screenshot, samples and callbacks establish this failure. The widget reopen case passes, but does not reproduce this full native sequence. The cause is not established; no shared-overlay workaround was attempted. Normal motion reaches an open Apple-only popup. All four captures retain the expected filtered content during the sampled close windows. Candidate input clears on Escape and displays Banana after selection.

The source no-results exit after selection displays Banana in its input and keeps the Fresh label, while the candidate clears its input and hides the empty group. This is a recorded difference, not a claim of complete source visual parity. Controlled ownership is widget evidence only; the native fixture is uncontrolled.
